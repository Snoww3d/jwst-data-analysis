# Plan: Bound thumbnail queue growth

- **Status:** approved
- **Spec:** [card-1104](../design/card-1104.md)
- **Branch:** `feature/card-1104`
- **Issue:** #1104

## Approach

Repair the existing channel and propagate async back-pressure through every
producer. CEO review holds the dispatched scope; engineering review confirms
all eight production enqueue sites already run in async methods. Sequential
implementation, no parallelization opportunity.

## Steps

1. Bound the queue and expose cancellable async enqueue with occupancy logging.
2. Await enqueue from all producers; migrate mocks and existing tests.
3. Add saturation, cancellation, and warning tests; update queue diagrams.
4. Run pre-commit build/analyzers and backend tests, review, push, and open PR.

## Files changed

| File | Change |
|------|--------|
| ThumbnailQueue.cs, IThumbnailQueue.cs | Bounded async contract and logging |
| DataScanService, StartupScanBackgroundService, MosaicService | Await enqueue |
| MastController, JwstDataController | Await enqueue |
| Queue, worker, and producer tests | Preserve coverage; add capacity regressions |
| Architecture concurrency and service-layer docs | Correct capacity descriptions |

## Test plan

1. Fill 50 batches, verify the next enqueue waits, consume one, then verify FIFO
   delivery of all remaining batches with no drop and eventual zero pending.
2. Cancel a waiting enqueue; verify no phantom batch or pending-count leak.
3. Fill to the warning threshold; verify warning includes occupancy and capacity.
4. Run the backend suite including existing empty, FIFO, worker-failure, scan,
   mosaic and controller coverage, and compile with warnings as errors.

## Rollback

Revert this PR as one change; no data migration is required.

## Blast radius

Thumbnail producers in imports, startup recovery, mosaic saves, and administrative
requests now await space. High-confidence regression risk: merely bounding
TryWrite would drop work; the async contract and saturation test prevent that.
Pending count includes waiting producers; the capacity warning uses only buffered
items. No diagrams change except the two existing unbounded-queue labels.

## Out of scope

No additional work proposed beyond issue #1104. ADR 0001 migration is unchanged.
