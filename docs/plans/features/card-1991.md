## Blast radius

Auth endpoints and users collection only. Wrong DTOs break frontend auth; wrong
hash/claim encoding invalidates existing credentials; non-atomic writes could revive
revoked sessions. Tests cover those seams. No production routing changes.

## Engineering review

Large by file/class count, warranted by the explicitly authorized three-endpoint
foundation; no smaller slice meets acceptance. Architecture sound with the following
changes incorporated before implementation:

- [P1] (confidence: 10/10) AuthService.cs refresh read/write is not atomic; use a
  conditional update and bounded retry to prevent replay/revocation races.
- [P1] (confidence: 10/10) Existing whole-user replacement can overwrite lockout
  state; use token-only $set and preserve unknown fields.
- [P1] (confidence: 10/10) bcrypt 5 rejects inputs over 72 bytes; explicitly reproduce
  BCrypt.Net truncation to keep existing 100-character password acceptance.
- [P1] (confidence: 9/10) Default FastAPI validation echoes submitted inputs; redact
  validation errors on auth routes so passwords/tokens cannot be reflected.

No unresolved scope decisions. Sequential implementation, no parallelization opportunity.
CPU-heavy bcrypt runs in the threadpool; database calls are bounded and indexed.

### TEST PLAN — Python auth foundation

Affected routes: register, login, refresh; existing token dependencies and CE boundary.
Key interactions: register→login→refresh→protected dependency; current→grace→replay;
concurrent registration and refresh. Edge cases: inactive/locked, missing fields,
long UTF-8 passwords, malformed stored hash, duplicate case-insensitive email,
unknown/null/expired tokens, missing settings and Mongo failure.

Coverage diagram (planned ★★★ behavior + edge + error coverage):

- models → bounds/complexity/DTO projection → test_auth_port.py
- service → register/login/refresh/issuance → test_auth_port.py
- users → lookups/indexes/targeted writes/CAS → tests/db/test_users.py
- routes → gate/validation/error/status → test_auth_port.py
- CRITICAL regression → existing require_user/require_role, CE excludes auth

Tests are API integration + unit + real Mongo, with no UI changes. Docker rebuild
is unnecessary: existing dependencies suffice; mount the exact branch source.
