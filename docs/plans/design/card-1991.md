# Spec: Python auth foundation

- **Status:** draft for human danger review; implementation authorized by #1991 dispatch
- **Intent:** [card-1991](../intent/card-1991.md)
- **Date:** 2026-09-09

## Summary

Port register/login/refresh to Python without enabling a production auth cutover.
Preserve existing .NET BSON and JWT contracts and isolate persistence behind an
injectable users repository.

## Requirements

| # | Requirement | Verified by |
|---|-------------|-------------|
| R1 | Existing BCrypt.Net passwords (including 72-byte truncation), username then case-insensitive email login; generic credential failures | auth contract tests |
| R2 | Register with existing length/complexity policy, lowercase email, User role, race-safe unique indexes; 201 response | registration and Mongo integration tests |
| R3 | HS256 shared secret/issuer/audience, URI role claim, 60-minute access / 7-day refresh defaults; only refresh hashes persisted | token round-trip tests |
| R4 | Refresh current and previous-grace hashes; rotate atomically; reject inactive/missing/expired tokens | refresh and concurrency tests |
| R5 | Explicit camelCase token/user DTO allowlist; sanitized validation and database errors | exact response-key and failure tests |
| R6 | Preserve FailedLoginAttempts/LockedUntil and unrelated fields via targeted updates; honor existing active lockouts | persistence tests |
| R7 | Disabled by default behind PYTHON_AUTH_ENABLED=true for isolated development; CE still excludes auth; no deploy/frontend changes | gate regression tests |
| R8 | Docker tests and linters pass; human approval required before merge | PR evidence |

## Approach

Routes validate bounded typed requests, invoke a service, and expose explicit DTOs.
The service offloads bcrypt to the threadpool, normalizes missing-user verification
with a dummy hash, issues .NET-compatible tokens and writes through a repository
Protocol. The Mongo adapter uses existing PascalCase fields and ObjectId IDs.
Registration ensures the existing named unique username/email indexes before insert;
index failures fail closed. Login updates only token fields and LastLoginAt. Refresh
uses compare-and-set plus one retry to handle simultaneous current-token requests
through the existing previous-token grace semantics without reviving revoked tokens.

### Alternatives rejected

| Option | Why not |
|--------|---------|
| Enable Python production auth immediately | Would bypass #1186 lockout-counter parity |
| Include admin unlock/counters now | Explicitly owned by #1186 |
| Replace entire user document | Can erase concurrent security changes and unknown fields |
| New password/token schema or passlib | Breaks compatibility; bcrypt already installed |

## Data model and API changes

POST /api/auth/register (201), /login (200), /refresh (200). Requests and responses
use camelCase, matching AuthModels.cs and frontend authService.ts. Failures retain
400 registration conflict, 401 credential/token failure and sanitized error envelopes.
Validation returns 400 without echoing submitted passwords/tokens. Invalid server
configuration or Mongo failures return a generic 503. No new collection or field.
Refresh tokens are 64 random bytes in Base64, stored as lowercase SHA-256 hex.
Normal refresh sets a 60-second previous-token grace; grace refresh clears it.
Missing/null expiry fails closed. Existing lockouts are honored at login/refresh;
failed-attempt increments and resets remain #1186.

Configuration: JWT_SECRET_KEY (minimum 32 characters), JWT_ISSUER, JWT_AUDIENCE,
JWT_ACCESS_TOKEN_EXPIRATION_MINUTES (60), JWT_REFRESH_TOKEN_EXPIRATION_DAYS (7),
JWT_REFRESH_TOKEN_GRACE_WINDOW_SECONDS (60), existing MONGODB_URI/DATABASE.
The opt-in requires write credentials. No default deployment configuration changes.

## Failure modes

| Failure | Detected how | Behaviour |
|---------|--------------|-----------|
| Unknown/bad password, inactive/locked user | Service verification | Same 401; no token write |
| Duplicate registration race | Unique Mongo indexes | Same generic 400 as precheck |
| Missing/expired/revoked refresh | Lookup and atomic write predicates | 401 |
| Mongo/index failure | Driver exception | Generic 503, no credentials in response/log |
| Invalid body/settings | Typed validation/config guard | Sanitized 400/503 |
| Rotation races with login/revoke/password change | Compare-and-set | Retry once, otherwise 401 |
