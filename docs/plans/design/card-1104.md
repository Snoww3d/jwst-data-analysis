# Spec: Bound thumbnail queue growth

- **Status:** approved for implementation by issue #1104 dispatch
- **Intent:** [Issue #1104](https://github.com/Snoww3d/jwst-data-analysis/issues/1104)
- **Date:** 2026-09-06

## Summary

Limit the existing thumbnail channel to 50 buffered batches. Producers await
space instead of allowing the channel to grow indefinitely during bulk imports.

## Requirements

| # | Requirement | Verified by |
|---|-------------|-------------|
| R1 | Buffer at most 50 batches; wait without dropping work when full | Saturation and FIFO regression test |
| R2 | Support cancellation of waiting producers and consistent pending accounting | Cancellation regression test |
| R3 | Warn when buffered occupancy reaches 80% of capacity | Logging regression test |
| R4 | Preserve empty-batch handling and all existing producers | Existing tests and build |

## Approach

Use a bounded channel with one reader and `FullMode.Wait`. Change the internal
enqueue contract to an awaited Task with an optional cancellation token. Pass
existing job and shutdown tokens where available. Count waiting, buffered, and
processing batches as pending; increment before publication so a fast consumer
cannot decrement before the producer increments. Roll back cancelled writes.
Warnings use buffered occupancy, not the pending count.

### Alternatives rejected

| Option | Why not |
|--------|---------|
| Bounded channel with unchanged TryWrite | Silently loses batches at capacity |
| Synchronously block writers | Occupies request threads while generation is slow |
| Drop oldest/newest | Prevents some imported records receiving thumbnails |

## Data model and API changes

No stored data, routes, auth, or DTO changes. The internal IThumbnailQueue method
becomes EnqueueBatchAsync. Requests may wait for queue space before returning.

## Failure modes

| Failure | Detected how | Behaviour |
|---------|--------------|-----------|
| Slow consumer | Occupancy warning at 40/50 | Producers await capacity |
| Cancelled enqueue | CancellationToken | Throw cancellation and restore pending count |
| Thumbnail generation failure | Existing worker catch/finally | Log and continue; decrement pending |

## Flagged concerns

No configured danger-zone paths. Capacity limits batches, not IDs or bytes per
batch; this is not a global process memory limit. Requests and jobs can take
longer under saturation. Existing producers without cancellation tokens continue
waiting until capacity is available. The repair targets the existing .NET queue
while ADR 0001 migration proceeds separately.

## Open questions carried forward

None. Capacity 50 follows the issue's initial recommendation; throughput tuning
can use occupancy warnings.
